Hexo博客评论系统从Gitalk迁移到Giscus
Hexo GitHub
发布日期:   2026-08-03
作者:   SK
文章字数:   901
阅读时长:   3 分
阅读次数:  

背景

博客一直在用 Gitalk 作为评论系统，是基于 GitHub Issues 的 OAuth 方案。最近发现评论区无法加载，控制台报 403 错误：

Error: Request failed with status code 403
https://cors-anywhere.herokuapp.com/https://github.com/login/oauth/access_token

问题排查

Gitalk 为什么挂了

Gitalk 的工作流程：用户点击登录 → 通过 CORS 代理向 GitHub 请求 OAuth token → 返回 token → 用户以 GitHub 身份评论。

问题出在 CORS 代理。Gitalk 默认用 cors-anywhere.herokuapp.com 这个公共代理，它从 2021 年起就严格限制外部访问了，直接返回 403。要修好需要：

  1. 自己部署一个 CORS 代理（Vercel 或 Cloudflare Workers）
  2. 同时 OAuth clientSecret 暴露在前端 JS 中，存在安全隐患

考虑维护成本和安全性，决定直接换方案。

为什么选 Giscus

Giscus 是 Gitalk 的现代替代品，基于 GitHub Discussions API：

对比项 Gitalk Giscus
数据存储 GitHub Issues GitHub Discussions
需要 clientSecret 是，暴露在前端 不需要
需要 CORS 代理 是，需自建 不需要
维护状态 2019 年停更 持续更新

迁移步骤

1. GitHub 仓库准备

  • 仓库 Settings → General → Features 中开启 Discussions
  • 安装 Giscus GitHub App，授权仓库

2. 获取配置参数

打开 giscus.app/zh-CN，输入仓库名 用户名/仓库名，页面自动检测仓库状态（需已开启 Discussions 且安装 Giscus App），通过后在页面下方自动生成配置脚本，从中取 data-repo-id 和 data-category-id。

3. 替换模板

在 Hexo 主题中新建 giscus.ejs，核心是一个 script 标签：

<script src="https://giscus.app/client.js"
    data-repo="用户名/仓库名"
    data-repo-id="R_xxx"
    data-category="Announcements"
    data-category-id="DIC_xxx"
    data-mapping="pathname"
    data-theme="preferred_color_scheme"
    data-lang="zh-CN"
    crossorigin="anonymous"
    async>
</script>

然后在文章详情模板 post-detail.ejs 中添加引用，停用原有的 Gitalk。

<% if (theme.giscus && theme.giscus.enable) { %>
    <%- partial('_partial/giscus') %>
<% } %>

4. 配置文件

在主题 _config.yml 中添加 Giscus 配置，同时禁用 Gitalk：

gitalk:
  enable: false

giscus:
  enable: true
  repo: 用户名/仓库名
  repoId: R_xxx
  category: Announcements
  categoryId: DIC_xxx
  mapping: pathname
  theme: preferred_color_scheme
  lang: zh-CN
  loading: lazy

移动端布局踩坑

迁移完成后，桌面端一切正常，但手机访问页面布局完全乱掉——这是另一个问题。

排查过程

手机浏览器打开开发者工具（Chrome 远程调试），发现 materialize.min.css 加载失败。博客用的是 Matery 主题，整个页面的栅格布局、卡片、导航全部依赖 Materialize CSS 框架。这个 CSS 配的是 cdn.bootcss.com 的外部 CDN，在移动网络下不稳定，偶尔加载超时就导致页面变成裸 HTML。

修复

把核心库从 CDN 切到站点本地文件：

文件 之前 (CDN) 之后 (本地)
materialize.min.css cdn.bootcss.com /libs/materialize/
materialize.min.js cdn.bootcss.com /libs/materialize/
jquery.min.js libs.baidu.com /libs/jquery/

本地文件本来就在主题目录里，只是之前注释掉了本地路径改用了 CDN。改回配置即可：

libs:
  css:
    materialize: /libs/materialize/materialize.min.css
  js:
    jquery: /libs/jquery/jquery-2.2.0.min.js
    materialize: /libs/materialize/materialize.min.js

这样只要网站能打开，样式就一定正常加载，不再受外部 CDN 影响。

总结

  1. Gitalk → Giscus：省去了自建 CORS 代理的麻烦，也不再需要把 OAuth secret 暴露在前端
  2. CDN → 本地：核心 CSS/JS 框架用本地文件更可靠，尤其是对国内移动网络环境
  3. 两个问题同时修完后，博客评论功能和移动端显示都恢复正常
